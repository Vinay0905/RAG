## 1. What Makes This Phase Hard

Six phases have accumulated decisions justified by reasoning rather than evidence. HyDE is off
because I argued it probably would not help. MMR is off for the same reason. `RRF_K=60` is the
number from the paper. `CACHE_SIMILARITY_THRESHOLD` is 0.97 because 0.92 looked dangerous. The
cross-encoder costs 20ms per query and I claimed it earns it.

Every one of those is a guess wearing a justification. This phase replaces them with numbers.

Three things make that harder than running a script.

**There is no labelled data, and hand-labelling 650,000 contracts is not happening.** Evaluation
needs question–answer pairs with known correct sources. Buying them is out; making them is the only
option, and a synthetic set generated by an LLM has a specific bias you must understand before
trusting it.

**Answer quality has no ground truth to compare against.** You can check whether retrieval found the
right chunk — that is set membership. "Is this answer good" is not. Any metric here is an LLM judging
an LLM, which Phase 5 §8 already established is lenient and correlated.

**A single evaluation number is nearly useless.** "Score: 0.82" answers no question you actually
have. The two questions worth answering are "did my change help" and "did this regress", and both
need comparison rather than measurement.

*(An earlier draft of this section also promised "which stage is losing recall". That needs
per-stage instrumentation — pre-fusion candidates, post-rerank ranks, arm-level results — threaded
through `RetrievalResult` and recorded per case. It is a genuine capability and roughly 200 lines,
and it is cut for budget. What this harness measures is the pipeline's final output. Bisect stages
by toggling flags and re-running, which is slower and costs nothing to build.)*

## 2. What Was Cut, and Why

Naming the cuts is more useful than listing the features, because the reasoning transfers.

**RAGAS.** The obvious move is to install the standard evaluation framework. Rejected: it brings a
LangChain dependency tree, its metrics are LLM-judged in ways I would have to explain anyway, and the
learning value of this phase is understanding *what* is being measured. Four metrics written by hand
teach more than twenty imported ones, and the imported ones would still need the synthetic dataset
this phase builds.

**A metrics dashboard.** Phase 9 has a UI. Numbers to stdout and a JSON file are enough to make
decisions, and a chart that nobody looks at twice is not worth 300 lines.

**Per-metric LLM judges for faithfulness, answer-correctness, context-precision, and
context-utilisation.** Kept two answer metrics, not five. Each additional judge is another LLM call
per case per run, and the marginal ones correlate heavily with groundedness. Two metrics you trust
beat five you average.

**Experiment tracking (MLflow, W&B).** A JSON file per run in `data/evaluations/` gives the same
comparison at this scale — but the run must record its own provenance, because `git log` cannot
reconstruct the environment variables it ran with. `_provenance()` in §7 captures the commit, the
dataset digest, the prompt version, every model ID, and every feature flag.

**Per-stage retrieval instrumentation** (§1) and **a `multi_hop` category** (§4). Both are real
capabilities, both are cut for budget, and both are described where they would have gone rather than
quietly omitted.

**Storing full source passages in the eval set.** `EvalCase.source_text` is capped at 600 characters
and `data/` is gitignored. The file is a second uncontrolled copy of contract text, and the prose
about it being "greppable and diffable in git" was describing a compliance problem approvingly.
Enough context to debug a bad case, not a corpus mirror.

**Continuous evaluation on a schedule.** Phase 10 wires `regression.py` into CI. Running it on a
timer against a corpus that does not change is spending money to redraw the same number.

That is roughly 700 lines not written. What remains is the part that changes decisions.

## 3. File 1 — `src/evaluation/dataset.py`

### The Problem

An evaluation case needs a question, the chunk IDs that answer it, and enough provenance to debug a
bad score. It has to survive between runs so today's number is comparable with last week's.

### Design Decision

**A Pydantic model and JSONL.** JSONL because an eval set is append-only, greppable, diffable in git,
and streamable — the same reasoning as Phase 2's checkpoint file. A single JSON array would have to
be rewritten whole on every append.

```python
import json
from datetime import datetime, timezone
from pathlib import Path

from pydantic import BaseModel, Field, field_validator


#: The two categories actually generated. `multi_hop` was planned and cut — see §2.
CATEGORIES = ("specific", "vague")


class EvalCase(BaseModel):
    """One question with known-correct sources.

    `source_chunk_ids` is what makes retrieval measurable without human judgement:
    the chunk this question was generated FROM is, by construction, a correct
    source for it.

    Validated rather than trusted. A corrupt or empty eval set produces zeros that
    look exactly like a system quality failure, and you will debug the retriever for
    an afternoon before checking the dataset.
    """

    case_id: str = Field(min_length=1)
    question: str = Field(min_length=15)
    #: Chunks that genuinely answer this. Never empty — a case with no expected
    #: source scores 0.0 on every retrieval metric no matter what the system does.
    source_chunk_ids: list[str] = Field(min_length=1)
    #: The passage the question came from, TRUNCATED. Kept for debugging a bad
    #: score: a question that turns out to be unanswerable is a dataset bug, not a
    #: retrieval failure, and you can only tell by reading this. Truncated because
    #: this file is a second, uncontrolled copy of contract text — see §2 on why it
    #: is capped and gitignored rather than stored whole.
    source_text: str = Field(default="", max_length=600, repr=False)
    contract_name: str = ""
    section_title: str = ""
    category: str = "specific"
    created_at: datetime = Field(default_factory=lambda: datetime.now(timezone.utc))

    @field_validator("category")
    @classmethod
    def _known_category(cls, v: str) -> str:
        if v not in CATEGORIES:
            raise ValueError(f"category must be one of {CATEGORIES}, got {v!r}")
        return v


class EvalResult(BaseModel):
    """What one case produced. Stored so a regression can be explained later."""

    case_id: str
    question: str
    category: str
    #: The expected IDs, copied in. Without them a saved run cannot be re-examined
    #: once the cases file changes — and the cases file is regenerated whenever the
    #: corpus does.
    expected_chunk_ids: list[str] = Field(default_factory=list)
    retrieved_chunk_ids: list[str] = Field(default_factory=list)
    answer: str = Field(default="", repr=False)
    scores: dict[str, float] = Field(default_factory=dict)
    #: Metrics that could not be computed. Distinct from a score of 0.0, which is a
    #: measurement. See §6.
    unmeasured: list[str] = Field(default_factory=list)
    #: Pipeline latency ONLY — excludes the evaluation judges. See §7.
    latency_ms: float = 0.0
    judge_ms: float = 0.0
    status: str = "answered"
    #: Cross-phase observability that exists specifically for this harness.
    cache_hit: bool = False
    grading_verified: bool = True
    invalid_citations: int = 0
    error: str | None = None


def save_cases(cases: list[EvalCase], path: Path, append: bool = False) -> None:
    """Write cases as JSONL.

    `append=False` overwrites, which is what a fresh generation wants. The default
    is explicit because the first draft called this "append-safe" and then opened
    with mode `"w"` — so a second `--generate` silently destroyed an eval set the
    prose said could be built up over weeks. Modes are cheap; contradicting your own
    docstring is not.
    """
    path.parent.mkdir(parents=True, exist_ok=True)
    with path.open("a" if append else "w", encoding="utf-8") as handle:
        for case in cases:
            handle.write(case.model_dump_json() + "\n")


def load_cases(path: Path) -> list[EvalCase]:
    """Read an eval set, skipping malformed lines loudly.

    A malformed line is skipped rather than fatal: an eval set built over weeks
    should not become unusable because one entry predates a schema change.
    """
    if not path.is_file():
        raise FileNotFoundError(f"No eval set at {path}. Run the generator first.")

    cases: list[EvalCase] = []
    seen: set[str] = set()
    skipped = 0

    for number, line in enumerate(path.read_text(encoding="utf-8").splitlines(), 1):
        if not line.strip():
            continue
        try:
            case = EvalCase.model_validate_json(line)
        except Exception as exc:
            print(f"  skipping line {number}: {type(exc).__name__}")
            skipped += 1
            continue
        if case.case_id in seen:
            skipped += 1
            continue
        seen.add(case.case_id)
        cases.append(case)

    if not cases:
        # An empty set is not "a run that scored zero", it is a broken dataset, and
        # letting it through produces a summary of zeros that reads as a total
        # system failure.
        raise ValueError(f"{path} contains no valid cases ({skipped} skipped)")
    if skipped:
        print(f"  loaded {len(cases)} cases, skipped {skipped}")
    return cases
```

## 4. File 2 — `src/evaluation/synthetic_generator.py`

### The Problem

You need a few hundred questions whose correct sources you know. Writing them by hand is a week of
work and produces questions biased toward what you happened to think of.

### Design Decision

**Generate questions *from* chunks, so the source is known by construction.** Sample a chunk, ask an
LLM to write a question it answers, and record the chunk ID. Retrieval is then measurable: did the
pipeline retrieve the chunk the question came from?

**Generate two categories**, matching Phase 5's router: `specific` (uses the document's own terms)
and `vague` (casual phrasing — the vocabulary-gap case Phase 4 exists for).

*(A `multi_hop` category was planned and is cut. Generating a question that genuinely requires two
specific chunks means finding pairs that relate, which needs either a graph over the corpus — Phase
13 — or an LLM pass over chunk pairs at quadratic cost. A "multi-hop" question generated from one
passage is not multi-hop, and shipping the label without the property would make `recall` look
measured when it is not. `CATEGORIES` has two members and the code generates two.)*

**Reject questions that reference the passage.** "What does this section say about termination?" is
unanswerable without knowing which section — and it is exactly what a model generates when shown one
passage. Filtering these is the difference between a usable set and a broken one.

```python
import random

from pydantic import BaseModel, Field

from src.core.interfaces import BaseLLMProvider, BaseVectorStore
from src.core.logging import logger
from src.core.models import ChunkLevel
from src.core.utils import hash_text
from src.guardrails.prompt_injection import neutralise_document

from .dataset import EvalCase

_SYSTEM = """You write evaluation questions for a legal contract search system.

Given a passage from a contract, write ONE question that the passage answers.

Rules:
- The question must be answerable from the passage alone.
- It must stand on its own. NEVER write "this section", "the above clause", "the
  passage", or "this agreement" — the person asking has not seen the passage and
  is searching a database of thousands of contracts.
- Include enough specificity to identify what is being asked about.
- Return only the JSON object.

Style for this question: {style}"""

_STYLES = {
    "specific": "Use the contract's own terminology and defined terms.",
    "vague": (
        "Use casual, everyday language, as a non-lawyer would ask. Deliberately "
        "AVOID the contract's formal terms."
    ),
}

#: Phrases that make a question unanswerable out of context. The single most
#: important filter here: a model shown one passage writes about "this section"
#: constantly, and every such case is an automatic retrieval failure that looks
#: like a system bug rather than a dataset bug.
_CONTEXT_DEPENDENT = (
    "this section", "this clause", "the above", "the passage", "this provision",
    "this agreement", "said agreement", "the text", "the contract", "herein",
    "the document", "this document", "as stated", "the following clause",
)


class GeneratedQuestion(BaseModel):
    question: str = Field(default="")


class SyntheticGenerator:
    """Corpus → evaluation cases with known-correct sources."""

    def __init__(self, store: BaseVectorStore, llm: BaseLLMProvider) -> None:
        self.store = store
        self.llm = llm

    async def generate(
        self, count: int = 100, seed: int = 42, min_tokens: int = 80
    ) -> list[EvalCase]:
        """Sample chunks and write one question each.

        `seed` is fixed so the same corpus produces the same eval set. An eval set
        that changes between runs makes every comparison meaningless — you cannot
        tell a real improvement from a different set of questions.
        """
        chunks = await self._sample(count * 4, seed, min_tokens)
        if not chunks:
            raise RuntimeError("No chunks available; has ingestion run?")

        cases: list[EvalCase] = []
        seen_questions: set[str] = set()
        rejected = 0
        duplicates = 0

        for chunk in chunks:
            if len(cases) >= count:
                break

            style = "vague" if len(cases) % 3 == 0 else "specific"
            question = await self._ask(chunk.text, style)

            if question is None or self._is_context_dependent(question):
                rejected += 1
                continue

            # Deduplicate. "What law governs this agreement?" is generated from
            # hundreds of different chunks, and duplicates overweight boilerplate
            # while shrinking the effective sample — with the summary still
            # reporting the raw count.
            fingerprint = " ".join(question.lower().split())
            if fingerprint in seen_questions:
                duplicates += 1
                continue
            seen_questions.add(fingerprint)

            cases.append(
                EvalCase(
                    # Derived from the chunk, not random. `uuid4` meant a
                    # regenerated set had entirely new IDs, so no saved run could be
                    # matched back to a case even when the question was identical.
                    case_id=hash_text(f"{chunk.chunk_id}:{style}")[:12],
                    question=question,
                    source_chunk_ids=[chunk.chunk_id],
                    source_text=chunk.text[:600],
                    contract_name=chunk.contract_name,
                    section_title=chunk.section_title,
                    category=style,
                )
            )

        if len(cases) < count:
            # Loud, because a short set silently changes what every subsequent
            # comparison means — and a category-skewed one changes it invisibly.
            logger.warning(
                "Generated fewer cases than requested",
                extra={"requested": count, "produced": len(cases),
                       "rejected": rejected, "duplicates": duplicates},
            )

        logger.info(
            "Generated evaluation set",
            extra={"cases": len(cases), "rejected": rejected, "duplicates": duplicates,
                   "vague": sum(1 for c in cases if c.category == "vague")},
        )
        return cases

    async def _sample(self, count: int, seed: int, min_tokens: int) -> list:
        """Random PARENT chunks above a size floor.

        Parents, because they are what generation actually sees after Phase 4's
        substitution. A size floor because a 40-token chunk yields a trivial
        question that every retriever answers, which inflates every score.

        Sampling is over a scrolled window rather than the whole 39-million-point
        collection — a genuinely uniform sample would need a full scan, and this is
        an eval set, not a survey.
        """
        records = await self.store.scroll_sample(
            limit=count * 5, filters={"chunk_level": ChunkLevel.PARENT.value}
        )
        eligible = [c for c in records if c.token_count >= min_tokens]
        random.Random(seed).shuffle(eligible)
        return eligible[:count]

    async def _ask(self, passage: str, style: str) -> str | None:
        # Contract text goes into a prompt here exactly as it does in generation, so
        # it gets the same treatment. An adversarial clause could otherwise instruct
        # the generator to write biased or broken evaluation questions — corpus
        # content manipulating the benchmark that approves retrieval changes, which
        # is a more valuable target than any single answer.
        safe_passage, _ = neutralise_document(passage)

        try:
            result = await self.llm.generate_json(
                prompt=f"Passage:\n\n{safe_passage}\n\nWrite one question it answers.",
                schema=GeneratedQuestion,
                system_prompt=_SYSTEM.format(style=_STYLES[style]),
                model=None,   # the default generation model; quality matters here
            )
        except Exception as exc:
            logger.warning("Question generation failed", extra={"error": type(exc).__name__})
            return None

        question = (result.question or "").strip()
        return question if len(question) > 15 else None

    @staticmethod
    def _is_context_dependent(question: str) -> bool:
        lowered = question.lower()
        return any(phrase in lowered for phrase in _CONTEXT_DEPENDENT)
```

### The Theory: the bias you are buying

A synthetic set generated this way has a specific, knowable bias, and using it without knowing that
is worse than not evaluating at all.

**The questions are answerable by construction.** Every one was written from a passage that exists in
the index. Real users ask questions the corpus does not answer, and this set contains none of them —
so it cannot measure how well the system says "I don't know". Phase 5's `NO_MATCH` path is invisible
here.

**The questions inherit the generator's vocabulary.** An LLM shown a passage tends to reuse its
terms even when told not to, which makes retrieval look easier than it is. The `vague` category
fights this and only partly wins. Expect real-world scores below these.

**One chunk is marked correct; others may be too.** A question about governing law is answered by
many contracts' governing-law clauses. Recall@k against a single ID under-counts. This makes the
metric *pessimistic*, which is the safe direction, but it means the absolute number means little.

The conclusion follows directly, and it is the thing to internalise: **these numbers are for
comparison, not for reporting.** "Retrieval hit rate 0.78" is not a claim about the system. "Hit rate
went from 0.78 to 0.84 when I enabled reranking, on the same 200 questions" is, and that is the only
claim this phase is built to make.

## 5. File 3 — `src/evaluation/metrics/retrieval.py`

### Design Decision

**Deterministic metrics only, no LLM.** Retrieval quality is set membership against known IDs, so
these are free, instant, and exactly reproducible — which is why they, not the answer metrics, are
what you tune against.

Three metrics, because they answer different questions:

- **Hit rate@k** — did the right chunk appear at all? The recall ceiling for everything downstream.
  If this is low, no reranker or prompt can save you.
- **MRR** — how high? `1/rank` of the first correct hit. Sensitive to ordering, which is what the
  reranker changes.
- **Recall@k** — what fraction of correct chunks were found? Matters only for multi-hop cases.

```python
from collections.abc import Sequence

from src.core.models import ScoredChunk


def hit_rate(retrieved: Sequence[ScoredChunk], expected: Sequence[str]) -> float:
    """1.0 if any expected chunk was retrieved, else 0.0.

    Averaged over a set, this is the fraction of questions whose answer was
    retrievable at all — the ceiling on everything the LLM can do afterwards.
    """
    if not expected:
        return 0.0
    found = _ids(retrieved)
    return 1.0 if found & set(expected) else 0.0


def mrr(retrieved: Sequence[ScoredChunk], expected: Sequence[str]) -> float:
    """Reciprocal rank of the first correct chunk. 0.0 if absent.

    Rank 1 → 1.0, rank 2 → 0.5, rank 5 → 0.2. The steep decay is deliberate and
    matches reality: with `RERANK_TOP_K=5` a correct chunk at rank 6 is not in the
    prompt at all, so the difference between rank 1 and rank 2 genuinely matters
    more than between 4 and 5.
    """
    wanted = set(expected)
    for position, scored in enumerate(retrieved, start=1):
        if scored.chunk.chunk_id in wanted:
            return 1.0 / position
    return 0.0


def recall_at_k(retrieved: Sequence[ScoredChunk], expected: Sequence[str]) -> float:
    """Fraction of expected chunks retrieved. Meaningful for multi-hop cases."""
    if not expected:
        return 0.0
    return len(_ids(retrieved) & set(expected)) / len(set(expected))


def _ids(retrieved: Sequence[ScoredChunk]) -> set[str]:
    """Chunk IDs, including parents' children.

    The subtlety that makes these metrics work at all: an `EvalCase` records the
    chunk a question was generated from, but Phase 4 substitutes PARENTS before
    returning. So the retrieved chunk is the parent of the expected chunk, its ID
    differs, and every metric would read 0.0 while retrieval worked perfectly.

    This handles ONE direction: a retrieved child counts as a hit for an expected
    parent. It cannot handle the reverse — a returned parent scored against an
    expected child — because resolving that needs a store lookup, and a metric
    function that hits the network is a metric you cannot unit-test.

    That direction is unnecessary rather than missing: the generator samples PARENT
    chunks (§4), so every expected ID is already a parent ID. If you ever build
    cases from children, expand them to their parents at generation time, not here.
    """
    found: set[str] = set()
    for scored in retrieved:
        found.add(scored.chunk.chunk_id)
        if scored.chunk.parent_id:
            found.add(scored.chunk.parent_id)
    return found
```

## 6. File 4 — `src/evaluation/metrics/answer.py`

### Design Decision

**Two LLM-judged metrics, implementing Phase 1's `BaseMetric`.** Groundedness and relevance — the
same two axes as Phase 5's grader, which is deliberate: this phase measures whether the *grader* is
working, and a metric that disagreed on definitions could not.

**A different prompt AND a different model.** Add one setting:

```python
    JUDGE_MODEL: str = Field(
        default="openai/gpt-oss-120b",
        description="Evaluation judge. MUST differ from GRADER_MODEL — see below.",
    )
```

with a runtime warning:

```python
        if self.JUDGE_MODEL == self.GRADER_MODEL:
            warnings.append(
                "JUDGE_MODEL equals GRADER_MODEL: evaluation measures agreement with "
                "the system's own grader rather than independent quality."
            )
```

This is not a detail. Phase 5 grades with `GRADER_MODEL`; if the evaluator judges with the same
model and a similar prompt, a shared blind spot appears as agreement, and the harness certifies the
grader's mistakes. The first draft said "ideally a different model" and then passed
`settings.GRADER_MODEL` to both metrics — a mitigation named in prose and absent from the code, which
is precisely the failure pattern the fourth lesson in the handoff describes.

Using the 120b to judge the 20b's grading is still the same family and therefore still correlated;
the honest position is that this reduces correlation rather than removing it. A genuinely
independent judge means a different vendor, which is a `.env` change away through the OpenAI
provider.

**Failure raises, it does not score.** See `MetricUnavailable` below.

```python
from pydantic import BaseModel, Field, model_validator

from config.settings import settings
from src.core.exceptions import RAGException
from src.core.interfaces import BaseLLMProvider, BaseMetric
from src.core.logging import logger

_GROUNDEDNESS_SYSTEM = """You measure how well an answer is supported by its sources.

Count the factual claims in the answer. Count how many are stated by the sources.
Return both numbers and list any claim that is not supported.

A claim that is true in general but absent from the sources is NOT supported.
Numbers, dates, and party names must match exactly."""

_RELEVANCE_SYSTEM = """You measure whether an answer addresses the question asked.

Return a score from 0.0 to 1.0:
  1.0 — fully answers the question
  0.5 — partially answers, or answers a related question
  0.0 — does not address the question

An honest "the sources do not state this" scores 1.0 if the sources genuinely do
not contain it: refusing to guess IS the correct answer."""


class MetricUnavailable(RAGException):
    """The judge could not produce a verdict.

    Raised instead of returning a sentinel. Phase 1 documents `BaseMetric.score` as
    returning `[0.0, 1.0]`, and the first draft returned `-1.0` on failure — so
    every caller typed against the interface had to know about a magic value the
    contract denies exists. Failure is not a low score; it is the absence of one,
    and the type system should say so. The evaluator catches this and records the
    metric as unmeasured.
    """


class GroundednessVerdict(BaseModel):
    total_claims: int = Field(default=0, ge=0)
    supported_claims: int = Field(default=0, ge=0)
    unsupported: list[str] = Field(default_factory=list)

    @model_validator(mode="after")
    def _coherent(self) -> "GroundednessVerdict":
        # Supported cannot exceed total. The first draft hid this with
        # `min(ratio, 1.0)`, so a judge returning "12 of 3 claims supported" scored
        # a perfect 1.0 — a malformed verdict rendered as the best possible result.
        if self.supported_claims > self.total_claims:
            raise ValueError(
                f"supported_claims ({self.supported_claims}) exceeds total_claims "
                f"({self.total_claims})"
            )
        return self


class RelevanceVerdict(BaseModel):
    score: float = Field(default=0.0, ge=0.0, le=1.0)
    reasoning: str = Field(default="", max_length=500)


class GroundednessMetric(BaseMetric):
    """Fraction of the answer's claims that the sources actually support.

    A ratio rather than a boolean, unlike Phase 5's grader. The grader needs a
    decision (retry or not); a metric needs resolution — "6 of 8 claims supported"
    tracks improvement in a way that pass/fail cannot.
    """

    def __init__(self, llm: BaseLLMProvider) -> None:
        self.llm = llm

    @property
    def name(self) -> str:
        return "groundedness"

    async def score(self, query: str, answer: str, contexts: list[str]) -> float:
        if not answer.strip():
            return 0.0
        if not contexts:
            # Retrieval returned nothing, so there is no grounding to measure.
            # Scoring 0.0 here would fold a RETRIEVAL failure into the GENERATION
            # metric, and overall groundedness would then track recall.
            raise MetricUnavailable("no contexts to ground against")

        try:
            verdict = await self.llm.generate_json(
                prompt=(
                    f"Question: {query}\n\nAnswer:\n{answer}\n\n"
                    f"Sources:\n\n" + "\n\n".join(contexts)
                ),
                schema=GroundednessVerdict,
                system_prompt=_GROUNDEDNESS_SYSTEM,
                model=settings.JUDGE_MODEL,
            )
        except Exception as exc:
            logger.warning("Groundedness scoring failed", extra={"error": type(exc).__name__})
            raise MetricUnavailable(f"judge failed: {type(exc).__name__}") from exc

        if verdict.total_claims <= 0:
            # Zero claims is only vacuously perfect if the answer really makes none.
            # A judge that fails to find claims in three paragraphs of assertions
            # would otherwise score a flat 1.0 — the worst judge output producing
            # the best possible number.
            if _looks_like_refusal(answer):
                return 1.0
            raise MetricUnavailable("judge found no claims in a substantive answer")

        return verdict.supported_claims / verdict.total_claims


class RelevanceMetric(BaseMetric):
    """Does the answer address the question?"""

    def __init__(self, llm: BaseLLMProvider) -> None:
        self.llm = llm

    @property
    def name(self) -> str:
        return "relevance"

    async def score(self, query: str, answer: str, contexts: list[str]) -> float:
        if not answer.strip():
            return 0.0

        # The sources are included because the prompt's own rule depends on them:
        # "a refusal scores 1.0 if the sources genuinely lack the answer" is a
        # judgement the judge cannot make without seeing the sources. The first
        # draft sent only the question and answer and then asked for that ruling.
        source_block = "\n\n".join(contexts) if contexts else "(no sources retrieved)"

        try:
            verdict = await self.llm.generate_json(
                prompt=f"Question: {query}\n\nAnswer:\n{answer}\n\nSources:\n\n{source_block}",
                schema=RelevanceVerdict,
                system_prompt=_RELEVANCE_SYSTEM,
                model=settings.JUDGE_MODEL,
            )
        except Exception as exc:
            logger.warning("Relevance scoring failed", extra={"error": type(exc).__name__})
            raise MetricUnavailable(f"judge failed: {type(exc).__name__}") from exc
        return verdict.score


def _looks_like_refusal(answer: str) -> bool:
    """Whether an answer declines rather than asserts."""
    lowered = answer.lower()
    return any(
        phrase in lowered
        for phrase in (
            "do not state", "does not state", "not contain", "no passages",
            "cannot answer", "not specified", "unable to determine",
        )
    )
```

## 7. File 5 — `src/evaluation/evaluator.py`

### Design Decision

**Bounded concurrency.** Two hundred cases sequentially at 3 seconds each is ten minutes; all at once
rate-limits the API. A semaphore of 5 is the compromise.

**Per-category breakdown, always.** An aggregate hides the finding: `specific` questions score well
and `vague` ones do not, which is exactly what tells you whether query expansion is working.

**Failures are recorded, not raised.** One case erroring must not lose the other 199.

```python
import asyncio
import json
import time
import uuid
from datetime import datetime, timezone
from pathlib import Path
from statistics import mean

from config.settings import settings
from src.core.interfaces import BaseMetric
from src.core.logging import logger

from .dataset import EvalCase, EvalResult
from .metrics.retrieval import hit_rate, mrr, recall_at_k


class Evaluator:
    """Runs an eval set through the service and aggregates the results."""

    def __init__(self, service, metrics: list[BaseMetric], concurrency: int = 5) -> None:
        if concurrency < 1:
            # A semaphore of 0 never releases a permit and the run hangs forever
            # with no output — the worst possible failure for a batch job.
            raise ValueError(f"concurrency must be at least 1, got {concurrency}")
        self.service = service
        self.metrics = metrics
        self._limit = asyncio.Semaphore(concurrency)

    async def run(self, cases: list[EvalCase]) -> list[EvalResult]:
        results = await asyncio.gather(*(self._one(case) for case in cases))
        return list(results)

    async def _one(self, case: EvalCase) -> EvalResult:
        async with self._limit:
            started = time.perf_counter()
            try:
                answer = await self.service.answer(case.question)
            except Exception as exc:
                # A failed case is data. Losing 199 results because one raised is not.
                return EvalResult(
                    case_id=case.case_id, question=case.question,
                    category=case.category, expected_chunk_ids=case.source_chunk_ids,
                    status="error", error=type(exc).__name__,
                )

            # STOP THE CLOCK HERE. Everything below is measurement, and the first
            # draft timed it — so `latency_p50_ms` was pipeline latency plus two
            # extra LLM calls, and every latency comparison in §9 ("does reranking
            # earn 20ms?") was measuring the judges instead.
            pipeline_ms = (time.perf_counter() - started) * 1000
            judge_started = time.perf_counter()

            retrieved = answer.sources
            scores = {
                "hit_rate": hit_rate(retrieved, case.source_chunk_ids),
                "mrr": mrr(retrieved, case.source_chunk_ids),
                "recall": recall_at_k(retrieved, case.source_chunk_ids),
            }
            unmeasured: list[str] = []

            contexts = [s.chunk.text for s in retrieved]
            for metric in self.metrics:
                try:
                    scores[metric.name] = await metric.score(
                        case.question, answer.answer, contexts
                    )
                except Exception:
                    # Per-metric isolation. Without it, one custom `BaseMetric` that
                    # raises takes down `asyncio.gather` and loses every result in
                    # the run — contradicting "failures are recorded, not raised".
                    unmeasured.append(metric.name)

            return EvalResult(
                case_id=case.case_id, question=case.question, category=case.category,
                expected_chunk_ids=case.source_chunk_ids,
                retrieved_chunk_ids=[s.chunk.chunk_id for s in retrieved],
                answer=answer.answer, scores=scores, unmeasured=unmeasured,
                latency_ms=pipeline_ms,
                judge_ms=(time.perf_counter() - judge_started) * 1000,
                status=answer.status.value,
                # Cross-phase observability. These fields exist because this harness
                # needs them: a run where half the answers were cache hits, or where
                # retrieval arms were failing, is not comparable to one where they
                # were not — and you cannot tell after the fact without recording it.
                cache_hit=answer.cache_hit,
                grading_verified=answer.grading.verified if answer.grading else True,
                invalid_citations=answer.invalid_citations,
            )


def aggregate(results: list[EvalResult], cases_digest: str = "") -> dict:
    """Mean per metric, overall and per category, plus everything needed to compare.

    Unmeasured metrics are excluded from the mean AND counted. Excluding alone was
    the first draft, and it hides the case that matters: if the judge fails
    preferentially on hard questions, the surviving mean rises while looking
    directly comparable to a baseline computed over the full set.
    """
    ok = [r for r in results if r.status != "error"]
    summary: dict = {
        "cases": len(results),
        "errors": len(results) - len(ok),
        "error_rate": round((len(results) - len(ok)) / len(results), 4) if results else 0.0,
        "overall": _means(ok),
        "measured": _measured_counts(ok),
        "by_category": {},
        # Status distribution. A grader outage flips answers to `unverified` while
        # independent judges still score the text highly — so quality metrics hold
        # steady and nothing fires. This is the only field that catches it.
        "status_counts": _counts(r.status for r in ok),
        "cache_hits": sum(1 for r in ok if r.cache_hit),
        "unverified": sum(1 for r in ok if not r.grading_verified),
        "latency_p50_ms": _percentile([r.latency_ms for r in ok], 0.5),
        "latency_p95_ms": _percentile([r.latency_ms for r in ok], 0.95),
        "judge_p50_ms": _percentile([r.judge_ms for r in ok], 0.5),
        "provenance": _provenance(cases_digest),
        "timestamp": datetime.now(timezone.utc).isoformat(),
    }

    for category in sorted({r.category for r in ok}):
        subset = [r for r in ok if r.category == category]
        summary["by_category"][category] = {"cases": len(subset), **_means(subset)}

    return summary


def _provenance(cases_digest: str) -> dict:
    """Everything needed to know what produced these numbers.

    A baseline without this cannot prove it used the same dataset or the same
    configuration, so "the score dropped" is unattributable — and `git log` cannot
    reconstruct environment variables that were never recorded.
    """
    import subprocess

    from src.graph.prompts import PROMPT_VERSION

    try:
        commit = subprocess.run(
            ["git", "rev-parse", "--short", "HEAD"],
            capture_output=True, text=True, timeout=5,
        ).stdout.strip()
    except Exception:
        commit = "unknown"

    return {
        "git_commit": commit,
        "cases_digest": cases_digest,
        "prompt_version": PROMPT_VERSION,
        "collection": settings.QDRANT_COLLECTION,
        "models": {
            "generation": settings.GENERATION_MODEL,
            "grader": settings.GRADER_MODEL,
            "judge": settings.JUDGE_MODEL,
            "embedding": settings.DENSE_MODEL_NAME,
            "reranker": settings.RERANK_MODEL_NAME,
        },
        "flags": {
            "multi_query": settings.ENABLE_MULTI_QUERY,
            "hyde": settings.ENABLE_HYDE,
            "reranking": settings.ENABLE_RERANKING,
            "mmr": settings.ENABLE_MMR,
            "parent_substitution": settings.ENABLE_PARENT_SUBSTITUTION,
            "self_correction": settings.ENABLE_SELF_CORRECTION,
        },
        "retrieval": {
            "retrieval_top_k": settings.RETRIEVAL_TOP_K,
            "rerank_top_k": settings.RERANK_TOP_K,
            "rrf_k": settings.RRF_K,
        },
    }


def _means(results: list[EvalResult]) -> dict[str, float]:
    names = {name for r in results for name in r.scores}
    return {
        name: round(mean(values), 4) if (values := [
            r.scores[name] for r in results if name in r.scores
        ]) else 0.0
        for name in sorted(names)
    }


def _measured_counts(results: list[EvalResult]) -> dict[str, int]:
    """How many cases each metric actually scored. Compared across runs."""
    names = {name for r in results for name in (*r.scores, *r.unmeasured)}
    return {name: sum(1 for r in results if name in r.scores) for name in sorted(names)}


def _counts(values) -> dict[str, int]:
    out: dict[str, int] = {}
    for value in values:
        out[value] = out.get(value, 0) + 1
    return out


def _percentile(values: list[float], fraction: float) -> float:
    """Linear-interpolated percentile.

    The naive `int(n * fraction)` returns the LARGER of two values for a p50 of two
    samples — not a median. Category subsets are small, so that error shows up
    exactly where the numbers are read most closely.
    """
    if not values:
        return 0.0
    ordered = sorted(values)
    if len(ordered) == 1:
        return round(ordered[0], 1)
    position = fraction * (len(ordered) - 1)
    low = int(position)
    high = min(low + 1, len(ordered) - 1)
    weight = position - low
    return round(ordered[low] * (1 - weight) + ordered[high] * weight, 1)


def save_run(summary: dict, results: list[EvalResult], directory: Path) -> Path:
    """Write one run to a uniquely-named JSON file.

    Per-case results are stored alongside the summary. When a number moves, the
    first question is always "which cases changed", and an aggregate cannot answer
    it. The suffix prevents two runs in the same second overwriting each other.
    """
    directory.mkdir(parents=True, exist_ok=True)
    stamp = datetime.now(timezone.utc).strftime("%Y%m%d-%H%M%S")
    path = directory / f"eval-{stamp}-{uuid.uuid4().hex[:6]}.json"
    path.write_text(
        json.dumps(
            {"summary": summary, "results": [r.model_dump() for r in results]},
            indent=2, default=str,
        ),
        encoding="utf-8",
    )
    logger.info("Evaluation saved", extra={"path": str(path), **summary["overall"]})
    return path


def digest_cases(cases: list[EvalCase]) -> str:
    """Stable fingerprint of an eval set, so a baseline knows what it measured."""
    from src.core.utils import hash_text

    return hash_text("|".join(sorted(c.case_id for c in cases)))[:16]
```

## 8. File 6 — `src/evaluation/regression.py`

### Design Decision

**Compare to a stored baseline; fail on a drop beyond tolerance.** This is what Phase 10 runs in CI.

**A tolerance, because LLM-judged metrics are noisy.** The same set scored twice differs by a few
percent. Failing on any decrease produces a check that cries wolf and gets disabled — which is worse
than no check.

```python
import json
from pathlib import Path

from src.core.logging import logger

#: LLM-judged metrics vary run to run; below this, a drop is noise.
JUDGED_TOLERANCE = 0.03
#: Retrieval metrics are DETERMINISTIC — same index, same query, same result. A
#: real 2% recall regression should not be absorbed because answer-judge noise set
#: the bound. One tolerance for both was simpler and let genuine retrieval
#: regressions through, which is the wrong direction to be simple in.
DETERMINISTIC_TOLERANCE = 0.005
_DETERMINISTIC = {"hit_rate", "mrr", "recall"}

#: Errors are excluded from every mean, so a run where the hard cases all crashed
#: keeps high scores on the easy survivors. This bounds that.
MAX_ERROR_RATE_INCREASE = 0.05
#: Same reasoning for judge coverage: a metric scored on 40% of cases is not
#: comparable to a baseline scored on 100%.
MAX_COVERAGE_DROP = 0.10


def _tolerance_for(metric: str) -> float:
    return DETERMINISTIC_TOLERANCE if metric in _DETERMINISTIC else JUDGED_TOLERANCE


def compare(current: dict, baseline: dict) -> list[str]:
    """Return a list of regressions. Empty means pass.

    Checks four things, not one. The first draft compared only `overall` means,
    which passes a run that: regressed badly on vague queries while specific ones
    held steady; crashed on a third of its cases; lost half its judge coverage; or
    flipped most answers to `unverified` because the grader broke.
    """
    failures: list[str] = []

    for metric, baseline_value in baseline.get("overall", {}).items():
        current_value = current.get("overall", {}).get(metric)
        if current_value is None:
            failures.append(f"{metric}: missing from the current run")
            continue
        drop = baseline_value - current_value
        if drop > _tolerance_for(metric):
            failures.append(
                f"{metric}: {baseline_value:.4f} → {current_value:.4f} "
                f"(down {drop:.4f}, tolerance {_tolerance_for(metric)})"
            )

    # Per category. This is where the finding lives, per §1 — an aggregate that
    # averages a stable `specific` set with a collapsed `vague` one looks fine.
    for category, baseline_scores in baseline.get("by_category", {}).items():
        current_scores = current.get("by_category", {}).get(category)
        if current_scores is None:
            failures.append(f"category {category}: missing from the current run")
            continue
        for metric, baseline_value in baseline_scores.items():
            if metric == "cases" or not isinstance(baseline_value, (int, float)):
                continue
            drop = baseline_value - current_scores.get(metric, 0.0)
            if drop > _tolerance_for(metric):
                failures.append(
                    f"{category}/{metric}: {baseline_value:.4f} → "
                    f"{current_scores.get(metric, 0.0):.4f} (down {drop:.4f})"
                )

    error_increase = current.get("error_rate", 0.0) - baseline.get("error_rate", 0.0)
    if error_increase > MAX_ERROR_RATE_INCREASE:
        failures.append(
            f"error rate: {baseline.get('error_rate', 0.0):.2%} → "
            f"{current.get('error_rate', 0.0):.2%}"
        )

    for metric, baseline_count in baseline.get("measured", {}).items():
        current_count = current.get("measured", {}).get(metric, 0)
        if baseline_count and (baseline_count - current_count) / baseline_count > MAX_COVERAGE_DROP:
            failures.append(
                f"{metric}: judged {current_count} cases vs {baseline_count} in the "
                "baseline — the means are not comparable"
            )

    baseline_unverified = baseline.get("unverified", 0)
    current_unverified = current.get("unverified", 0)
    if current_unverified > baseline_unverified + max(2, 0.1 * baseline.get("cases", 0)):
        failures.append(
            f"unverified answers: {baseline_unverified} → {current_unverified} "
            "(the grader may be failing)"
        )

    return failures


def validate_for_baseline(summary: dict, min_cases: int = 30) -> list[str]:
    """Reasons this run must NOT become the baseline. Empty means it may.

    Promotion is the moment a run becomes the standard everything is judged
    against, so it is the one place worth being strict. The first draft promoted
    any completed summary and auto-created a baseline when none existed — so a
    broken first run silently became the reference.
    """
    problems: list[str] = []

    if summary.get("cases", 0) < min_cases:
        problems.append(f"only {summary.get('cases', 0)} cases (need {min_cases})")
    if summary.get("error_rate", 0.0) > 0.05:
        problems.append(f"error rate {summary.get('error_rate', 0.0):.2%} is above 5%")
    if not summary.get("overall"):
        problems.append("no metrics were computed")
    if summary.get("cache_hits", 0):
        problems.append(
            f"{summary['cache_hits']} answers came from cache — the run measured "
            "stored answers, not the current configuration"
        )
    for metric, count in summary.get("measured", {}).items():
        if count < summary.get("cases", 0) * 0.8:
            problems.append(f"{metric} was only scored on {count} cases")

    return problems


def load_baseline(path: Path) -> dict | None:
    if not path.is_file():
        logger.warning("No baseline; this run becomes one", extra={"path": str(path)})
        return None
    return json.loads(path.read_text(encoding="utf-8"))


def save_baseline(summary: dict, path: Path) -> None:
    """Promote a run to the baseline. A deliberate act, never automatic —
    otherwise a bad run silently becomes the standard everything is measured against."""
    path.parent.mkdir(parents=True, exist_ok=True)
    path.write_text(json.dumps(summary, indent=2, default=str), encoding="utf-8")
    logger.info("Baseline updated", extra={"path": str(path)})
```

```python
"""Generate an eval set, run it, compare against the baseline.

    python scripts/evaluate.py --generate 100     # build the set (LLM calls)
    python scripts/evaluate.py                    # run it
    python scripts/evaluate.py --promote          # make this run the baseline
"""
import argparse
import asyncio
import sys
from pathlib import Path

from config.settings import settings
from src.app import build_service
from src.evaluation.dataset import load_cases, save_cases
from src.evaluation.evaluator import Evaluator, aggregate, digest_cases, save_run
from src.evaluation.metrics.answer import GroundednessMetric, RelevanceMetric
from src.evaluation.regression import (
    compare,
    load_baseline,
    save_baseline,
    validate_for_baseline,
)
from src.evaluation.synthetic_generator import SyntheticGenerator

EVAL_DIR = Path("data/evaluations")
CASES = EVAL_DIR / "cases.jsonl"
BASELINE = EVAL_DIR / "baseline.json"


async def main(args: argparse.Namespace) -> int:
    # BOTH CACHES OFF, before the service is built. This is the single most
    # important line in the file. With caching on, a second run answers previously
    # evaluated questions from Redis — skipping retrieval, generation, grading, and
    # self-correction entirely — so the harness measures last week's answers and
    # reports this week's configuration. Every ablation in §9 would be meaningless,
    # and the latency numbers would be cache latency.
    #
    # It also removes the within-run hazard: five cases run concurrently through one
    # service, and a completed case lands in the shared semantic index while others
    # are still going, so near-duplicate synthetic questions answer each other and
    # results become scheduling-dependent.
    settings.ENABLE_EXACT_CACHE = False
    settings.ENABLE_SEMANTIC_CACHE = False

    # Ablations must isolate what they claim to isolate. With self-correction on, a
    # failed first answer triggers a rewrite and a SECOND retrieval, so an
    # experiment on reranking also measures the correction loop's compensation.
    if args.no_correction:
        settings.ENABLE_SELF_CORRECTION = False

    service = await build_service()
    try:
        if args.generate:
            generator = SyntheticGenerator(service.store, service.llm)
            cases = await generator.generate(count=args.generate)
            save_cases(cases, CASES)
            print(f"Wrote {len(cases)} cases to {CASES}")
            return 0

        cases = load_cases(CASES)
        print(f"Running {len(cases)} cases (caches disabled)...")

        evaluator = Evaluator(
            service,
            metrics=[GroundednessMetric(service.llm), RelevanceMetric(service.llm)],
        )
        results = await evaluator.run(cases)
        summary = aggregate(results, cases_digest=digest_cases(cases))
        save_run(summary, results, EVAL_DIR)

        print(f"\n  overall: {summary['overall']}")
        for category, scores in summary["by_category"].items():
            print(f"  {category:>10}: {scores}")
        print(f"  measured: {summary['measured']}")
        print(f"  status:   {summary['status_counts']}")
        print(f"  latency p50={summary['latency_p50_ms']}ms "
              f"p95={summary['latency_p95_ms']}ms (judges: "
              f"{summary['judge_p50_ms']}ms)  errors={summary['errors']}")

        if args.promote:
            problems = validate_for_baseline(summary)
            if problems:
                print("\n✗ refusing to promote:")
                for problem in problems:
                    print(f"  {problem}")
                return 1
            save_baseline(summary, BASELINE)
            print(f"\n✓ baseline updated ({BASELINE})")
            return 0

        baseline = load_baseline(BASELINE)
        if baseline is None:
            # Do NOT auto-promote. The first draft did, so a broken first run became
            # the standard silently — and every later run was then measured against
            # it and passed.
            print(f"\nNo baseline. Review the numbers above, then run --promote.")
            return 0

        if baseline.get("provenance", {}).get("cases_digest") != summary["provenance"]["cases_digest"]:
            print("\n⚠ the eval set changed since the baseline; scores are not comparable")

        failures = compare(summary, baseline)
        if failures:
            print("\n✗ REGRESSION")
            for failure in failures:
                print(f"  {failure}")
            return 1

        print("\n✓ no regression")
        return 0
    finally:
        await service.llm.close()
        await service.store.close()
        await service.embedder.close()
        await service.cache.exact.close()


if __name__ == "__main__":
    parser = argparse.ArgumentParser()
    parser.add_argument("--generate", type=int, default=0)
    parser.add_argument("--promote", action="store_true")
    parser.add_argument("--no-correction", action="store_true",
                        help="Disable self-correction, for retrieval-only ablations.")
    sys.exit(asyncio.run(main(parser.parse_args())))
```

### The experiments to actually run

This is the deliverable. Each is one `.env` change, one run, one comparison — and each answers a
question that has been open since the phase that raised it.

| Change | Question | What would justify shipping it |
| :--- | :--- | :--- |
| `ENABLE_RERANKING=false` | Does the cross-encoder earn 20ms? | MRR drops materially when off |
| `ENABLE_MULTI_QUERY=false` | Does expansion earn ~400ms and an LLM call? | Hit rate drops, mostly on `vague` |
| `ENABLE_HYDE=true` | Does HyDE help on this corpus? | Hit rate rises beyond tolerance |
| `ENABLE_MMR=true` | Does diversity help or hurt? | Groundedness rises, MRR does not fall |
| `RRF_K=20` / `RRF_K=100` | Is 60 right here? | MRR moves; the paper's value is not law |
| `RERANK_TOP_K=3` / `10` | More context, or more noise? | Groundedness vs latency |
| `ENABLE_SELF_CORRECTION=false` | Does the retry loop improve answers? | Groundedness drops when off |
| `ENABLE_SEMANTIC_CACHE=true`, hits logged | Does it ever return a wrong answer? | **Zero false hits over the full set**, and a hit rate worth the risk |
| `CACHE_SIMILARITY_THRESHOLD` 0.95 / 0.97 / 0.99 | Where is the safe floor? | The lowest value with zero false hits |

The last two need a different procedure from the rest, and it is worth saying how. Run the set
**twice** with the cache on, and diff the answers: every case whose second answer differs from its
first is a cache hit, and any hit whose answer no longer fits the question is a false hit. **One
false hit in 200 cases disqualifies the feature** — this is the component that can be confidently
wrong, and a 30% hit rate does not buy back a single wrong answer about a liability cap. Run it
before considering turning that default back on.

Every row above **except** the self-correction one should be run with `--no-correction`. The retry
loop compensates for weak retrieval by rewriting and searching again, so with it enabled a reranking
ablation measures reranking plus the correction loop's response to its absence — which is exactly
the effect the experiment is trying to isolate.

Two predictions worth recording before you look, because a prediction you wrote down is the only
protection against reading a result as confirmation: **reranking will pay for itself, and HyDE will
not** — multi-query already closes most of the register gap on a corpus whose formal vocabulary the
expansion prompt targets directly. If HyDE does help here, that is genuinely interesting and worth
understanding before enabling it.

The metrics are pure functions, so most of this needs nothing running. Save as

```python
"""Phase 7 verification. No Qdrant, no API key."""
import sys
from pathlib import Path

from src.core.models import Chunk, ChunkLevel, ScoredChunk
from src.core.utils import make_chunk_id, make_doc_id, make_section_id
from src.evaluation.dataset import EvalCase, EvalResult, load_cases, save_cases
from src.evaluation.evaluator import _percentile, aggregate
from src.evaluation.metrics.retrieval import hit_rate, mrr, recall_at_k
from src.evaluation.regression import compare, validate_for_baseline
from src.evaluation.synthetic_generator import SyntheticGenerator

DOC = make_doc_id("data/contracts/2003/e.txt")
SEC = make_section_id(DOC, "Termination", 0)


def chunk(index: int, parent: str | None = None) -> Chunk:
    return Chunk(
        chunk_id=make_chunk_id(DOC, SEC, index), doc_id=DOC, section_id=SEC,
        text=f"Clause {index}.", chunk_index=index, token_count=20,
        section_title="Termination",
        chunk_level=ChunkLevel.CHILD if parent else ChunkLevel.PARENT,
        parent_id=parent,
    )


def scored(chunks: list[Chunk]) -> list[ScoredChunk]:
    return [ScoredChunk(chunk=c, score=1.0 - i * 0.1, rank=i) for i, c in enumerate(chunks)]


def check_retrieval_metrics() -> None:
    results = scored([chunk(0), chunk(1), chunk(2)])
    target = chunk(1).chunk_id

    assert hit_rate(results, [target]) == 1.0
    assert hit_rate(results, [make_chunk_id(DOC, SEC, 99)]) == 0.0
    assert mrr(results, [target]) == 0.5, "the second result must score 1/2"
    assert mrr(results, [chunk(0).chunk_id]) == 1.0
    assert mrr(results, ["absent"]) == 0.0
    assert recall_at_k(results, [chunk(0).chunk_id, chunk(1).chunk_id]) == 1.0
    assert recall_at_k(results, [chunk(0).chunk_id, "absent"]) == 0.5

    # The parent-substitution case. Phase 4 returns parents, so a case whose
    # expected ID is a CHILD must still score — otherwise every metric reads 0.0
    # while retrieval works perfectly, and you spend a day debugging the retriever.
    parent = chunk(1_000_000)
    child = chunk(5, parent=parent.chunk_id)
    assert hit_rate(scored([parent]), [parent.chunk_id]) == 1.0
    assert hit_rate(scored([child]), [parent.chunk_id]) == 1.0, (
        "a retrieved child must count as a hit for its parent"
    )

    print("✓ retrieval metrics: hit rate, MRR, recall, parent/child equivalence")


def check_question_filter() -> None:
    """Context-dependent questions must be rejected — they are unanswerable."""
    reject = SyntheticGenerator._is_context_dependent
    for bad in (
        "What does this section say about termination?",
        "According to the above clause, who pays?",
        "What is the notice period in this provision?",
    ):
        assert reject(bad), f"failed to reject a context-dependent question: {bad!r}"
    for good in (
        "What is the notice period for termination for convenience?",
        "Who indemnifies whom under the Acme purchase agreement?",
    ):
        assert not reject(good), f"rejected a good question: {good!r}"
    print("✓ question filter: context-dependent questions rejected")


def check_aggregation() -> None:
    results = [
        EvalResult(case_id="1", question="q", category="specific",
                   scores={"hit_rate": 1.0, "groundedness": 0.8}, latency_ms=100),
        EvalResult(case_id="2", question="q", category="vague",
                   scores={"hit_rate": 0.0}, unmeasured=["groundedness"], latency_ms=200),
        EvalResult(case_id="3", question="q", category="vague",
                   status="error", error="Boom"),
    ]
    summary = aggregate(results)

    assert summary["errors"] == 1, "errored cases must be counted, not dropped silently"
    assert summary["overall"]["hit_rate"] == 0.5
    assert summary["overall"]["groundedness"] == 0.8, (
        "an unmeasured metric must lower the SAMPLE SIZE, not the score — averaging a "
        "failure in makes a flaky judge look like a quality regression"
    )
    assert summary["measured"]["groundedness"] == 1, (
        "the number of cases each metric actually scored must be recorded, or a run "
        "judged on half its cases looks comparable to one judged on all of them"
    )
    assert set(summary["by_category"]) == {"specific", "vague"}
    assert summary["status_counts"], "the status distribution must be recorded"
    assert "provenance" in summary and summary["provenance"]["flags"], (
        "a run that does not record its configuration cannot be compared to another"
    )

    # p50 of two values is their mean, not the larger one.
    assert _percentile([100.0, 200.0], 0.5) == 150.0
    assert _percentile([100.0], 0.5) == 100.0
    print("✓ aggregation: coverage counted, statuses recorded, provenance captured")


def check_regression() -> None:
    baseline = {
        "overall": {"mrr": 0.70, "groundedness": 0.85},
        "by_category": {"vague": {"cases": 50, "mrr": 0.60}},
        "measured": {"groundedness": 100}, "error_rate": 0.0,
        "cases": 100, "unverified": 0,
    }

    def run(**overrides) -> dict:
        return {
            "overall": {"mrr": 0.70, "groundedness": 0.85},
            "by_category": {"vague": {"cases": 50, "mrr": 0.60}},
            "measured": {"groundedness": 100}, "error_rate": 0.0,
            "cases": 100, "unverified": 0, **overrides,
        }

    assert not compare(run(overall={"mrr": 0.699, "groundedness": 0.84}), baseline), (
        "noise-level drops must not fail — a check that cries wolf gets disabled"
    )
    # Deterministic metrics get a tight tolerance; 0.02 of MRR is a real regression.
    assert compare(run(overall={"mrr": 0.68, "groundedness": 0.85}), baseline), (
        "a 0.02 MRR drop is deterministic and must fail, whatever the judge noise is"
    )
    assert compare(
        run(by_category={"vague": {"cases": 50, "mrr": 0.30}}), baseline
    ), "a category collapse hidden by a stable overall mean must fail"
    assert compare(run(error_rate=0.30), baseline), (
        "a run where 30% of cases crashed must fail, not pass on the easy survivors"
    )
    assert compare(run(measured={"groundedness": 40}), baseline), (
        "a metric judged on 40 of 100 cases is not comparable to the baseline"
    )
    assert compare(run(unverified=60), baseline), (
        "a grader outage flipping answers to unverified must fail"
    )
    assert compare({"overall": {"groundedness": 0.85}}, baseline), (
        "a metric vanishing from a run is a failure, not a pass"
    )
    print("✓ regression: category, error-rate, coverage, and grader-health gates fire")


def check_baseline_promotion() -> None:
    """A bad run must not become the standard."""
    good = {"cases": 100, "error_rate": 0.0, "overall": {"mrr": 0.7},
            "measured": {"mrr": 100}, "cache_hits": 0}
    assert not validate_for_baseline(good)

    assert validate_for_baseline({**good, "cases": 5}), "a tiny set must not promote"
    assert validate_for_baseline({**good, "error_rate": 0.4}), "a broken run must not promote"
    assert validate_for_baseline({**good, "cache_hits": 12}), (
        "a run served from cache measured stored answers, not the configuration"
    )
    assert validate_for_baseline({**good, "measured": {"mrr": 20}}), (
        "a run judged on 20% of cases must not become the reference"
    )
    print("✓ promotion: short, broken, cached, and under-judged runs all refused")


def check_roundtrip(tmp: Path) -> None:
    cases = [EvalCase(case_id="a", question="What is the notice period?",
                      source_chunk_ids=["x"], category="specific")]
    path = tmp / "cases.jsonl"
    save_cases(cases, path)
    assert load_cases(path)[0].question == cases[0].question

    path.write_text(path.read_text() + "{not json}\n", encoding="utf-8")
    assert len(load_cases(path)) == 1, "a malformed line must be skipped, not fatal"
    print("✓ dataset: JSONL round-trip, malformed lines skipped")


def main() -> int:
    import tempfile

    try:
        check_retrieval_metrics()
        check_question_filter()
        check_aggregation()
        check_regression()
        check_baseline_promotion()
        with tempfile.TemporaryDirectory() as tmp:
            check_roundtrip(Path(tmp))
    except AssertionError as exc:
        print(f"\n✗ FAILED: {exc}")
        return 1
    print("\nPhase 7 verified.")
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

## 11. What Phase 7 Bought You

**The ability to answer "did that help?"** Every optional feature in Phases 4–6 now has a procedure
for deciding whether to ship it, and two of them (`ENABLE_HYDE`, `ENABLE_MMR`) have been waiting for
exactly this since they were written.

**A regression gate.** Phase 10 runs `scripts/evaluate.py` in CI. A prompt edit that improves one
thing and breaks another gets caught by the run, not by a user.

**Numbers that are honest about what they are.** §4 states the synthetic set's three biases plainly:
answerable by construction, vocabulary-contaminated, and single-source. These numbers compare runs;
they do not describe the system. Anyone who quotes an absolute score from this harness as a claim
about quality has misread it.

**A per-category breakdown**, which is where the actual finding will be. The aggregate will be
unremarkable; `specific` versus `vague` is where you will see whether Phase 4's whole reason for
existing works.

### What is deliberately not here

**Human evaluation.** The only way to truly validate an LLM judge is to disagree with it on a sample
by hand. Fifty cases read manually would tell you more about metric quality than any amount of code —
it is a task, not a file, and it belongs in the runbook.

**Anything that measures the "I don't know" path.** The synthetic set contains no unanswerable
questions, so `NO_MATCH` is invisible to it. Adding adversarial cases is a genuine gap and one file
of work; it is on the Phase 10 list rather than here because it needs hand-written cases.
